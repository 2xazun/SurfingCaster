## 📝 커밋 메시지 규칙

`<type>: <내용>` 형식으로 작성

| type | 의미 |
|---|---|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `style` | CSS/디자인 변경 (기능 변화 없음) |
| `refactor` | 코드 구조 개선 (기능 변화 없음) |
| `docs` | 문서(README 등) 수정 |
| `chore` | 설정, 빌드 등 기타 작업 |

**예시**
feat: 카카오맵 초기화 및 관측소 마커 렌더링 구현
fix: 마커 클릭 시 사이드바 데이터 안 뜨는 버그 수정

**규칙**
- 기능 하나 = 커밋 하나 (여러 기능 한 커밋에 몰아넣지 않기)
- 'feature/기능명' 브랜치에서 작업 후 PR (main에 직접 push x)
